## The design fact
Every check runs as the operator's own user on the same host, so the agent satisfies any of them. Measured reachable surface of THIS harness: **the operator terminal panel is agent-readable** (`mcp__terminal__read_terminal` returned the live prompt) and a browser pane is drivable; the arbitrary/secure desktop is not. | Option | Cost | Residual under computer-use |
|---|---|---|
| (a) 2nd-account ACL + `runas` | 2 cmds, once | `runas` has no password flag (measured: prompts, ignores piped stdin, exit 1) — holds UNLESS `/savecred` is used or the operator's user is admin over the dir |
| (b) terminal nonce | trivial (~10 lines) | **Defeated now** — `read_terminal` hands the agent the nonce with no computer-use at all; screenshot/OCR otherwise. Worthless in this harness as stated |
| (c) interactive prompt | ~ | Collapses to (b)/(d): the launcher manufactures a console the harness never touched; feeding Enter via redirected stdin re-trips `IsInputRedirected` (fail-closed), so the robust form needs a secret the agent lacks |
| (d) hardware/OS credential | high (~1–2 d) | **Secret never reaches the agent surface** — the secure (Winlogon) desktop is uncapturable by user-session screenshot APIs and uninjectable by SendInput; a hardware key needs physical touch |

Only **(d)** passes the "secret never on the agent's surface" test; (a) only conditionally.

## Recommendation — compose-and-confirm console on (d)+(a)
Relocate the gate-dir write ACL to a second principal (the agent-as-operator can no longer write it). Mint verbs stop writing; they hand a composed artifact to a long-lived console running as that principal. Flow:
1. **PLACEMENT** — the gate directory's write ACL belongs to a `gate-owner` principal the operator's interactive user cannot write; the mint verbs hand a fully-composed artifact to the console helper that runs as / impersonates that principal. This removes the agent's ability to write the gate dir at all, independent of any prompt.
2. **COMPOSE** (agent-allowed, non-authorizing) — anyone drops a REQUEST file (kind/id/binds) into an agent-writable inbox. Composing is not authorizing; this is legitimate work an agent should do.
3. **PREVIEW** — the console picks up the request, RE-DERIVES `binds_sha256` itself (never trusts the request), and renders the EXACT artifact bytes it would write, plus the resolved bind path and hash.
4. **CONFIRM** — the operator presses ONE key; that keypress triggers an OS credential on the **secure desktop** (Windows Hello / FIDO2 touch / UAC consent). Only on success does the console write the artifact to the ACL-restricted gates dir. One touch = one gate.
5. **ATTEST** — on write, the console appends a CONTENT-FREE line (UTC timestamp, request id, sha of the previewed bytes) to an operator-act log, reusing the WP-6 pattern in `tools/lam/record-operator-prompt.ps1:24-28`, giving the zero-paste attestation its independent second record.

Forbid `runas /savecred` and secure-desktop PIN-on-normal-desktop fallback, or the hole reopens; the operator's own user must not hold admin/take-ownership over the gate dir, or it re-ACLs around the control. Keep the four in-tool predicates as defence-in-depth but stop calling them (or the guard) the boundary. **Build cost:** the secure-desktop/Hello confirmation is the expensive piece (OS-specific WebAuthn or `CredUIPromptForWindowsCredentials`, ~1–2 days including the fail-closed path when no authenticator is enrolled, e.g. CI); ACL relocation + inbox/preview/write console + attestation ≈ a day.

## Fork for the operator
**(A)** Build (d)+(a) — the only design measured to keep the authorizing secret off every surface this agent reaches (~2–3 days, an OS-credential dependency, a fail-closed story for hosts with no authenticator). **(B)** Ship the next-gen guard now (adds the tripwire the live sealed guard lacks) + keep the tool's self-refusal — cheap, days, but **MEASURED insufficient**: the launcher shape returns False on the next-gen tripwire and the self-refusal is launcher-defeated, so an agent that constructs a scrubbed console still mints. Choosing (B) alone leaves the hole open by construction; (A) is the only branch that answers "an agent cannot mint," and even it rests on the secure desktop staying unreachable. **The most urgent immediate fact, independent of the fork: the LIVE sealed guard has NO gate-mint tripwire at all** — shipping the next-gen guard is necessary-but-not-sufficient and must not be sold as the fix.

## Residual under computer-use
A computer-use agent could still: (1) freely COMPOSE requests — expected and harmless, since authorization is the touch, not the request; (2) with full DESKTOP computer-use (not this harness — this one only reads the terminal panel and drives a browser pane), screenshot/inject the ORDINARY desktop, so the preview and the one-key press must live behind the SECURE desktop or a hardware touch, never a plain `Read-Host`; (3) attack the WEAKEST enrolled authenticator — a Hello PIN typed on the ordinary desktop is keylog-reachable, so the design must require the biometric/key/secure-desktop path and disable PIN-on-normal-desktop fallback; (4) if the operator ever enables `runas /savecred` for the gate-owner account, every later mint runs with no prompt; (5) social-engineer the operator into touching the key for an agent-composed request whose preview the operator does not read — which is exactly why the re-derived, un-scrollable-past PREVIEW is load-bearing. What it CANNOT do, measured: read a nonce never printed to the terminal panel, supply a `runas` password it does not know, or inject into the Winlogon secure desktop from a user-session or browser-pane surface.

# ITEM 2 — THE WAKE PRIMITIVE

## What was measured
CLI is **2.1.258** (`claude --version`). The surveyor drove throwaway sessions in an isolated scratch dir (no Stop hook) and read — never wrote — the two real files. Controls held: a bogus-uuid resume errors ("No conversation found", exit 1), so the append result below is trusted.

**The CLI has no live-injection.** Three measurements:
- `--resume -p` on a **running** session is **refused** (exit 1): *"Session … is running as a background session … `claude stop …` first to resume it here. Add `--fork-session` to branch off a copy instead."*
- `--fork-session` mints a **new** session id, a copy read from disk.
- `--resume -p` on a **stopped** session **appends** to the same `.jsonl` (21→29 lines) — pure disk-transcript replay.

`attach` (help: "Open a background session in this terminal") only re-fronts a *background* session's TTY; there is no path into an already-interactive orchestrator.

**The harness has a live-inject, but not for a headless runner.** `mcp__ccd_session_mgmt__send_message` and SendMessage-to-peer do deliver into a live session, but `claude mcp list` in a plain runner shows only the user's configured servers — the `ccd_*` tools are desktop-orchestrator in-process tools, absent from a `claude -p` runner. **This distinction is the finding: no live-inject exists at the layer a wake author (a runner) can reach.**

**The Stop-hook wedge** (`../<project>/.claude/settings.local.json:26-31`, `timeout 1800`; `mission-goal-check.ps1 -AsStopHook`, `decision: block` on NOT_MET at `:119`) means a headless `-p` wake at the repo root is re-prompted to an empty result and **held up to 1800 s** — confirmed from source.

## The proposal — an operator-run starter
Since no CLI live-inject exists, build **`tools/lam/lam-wake.ps1`** (PS 5.1), run by the operator from the main checkout. It removes the copy-paste; it does **not** create worktrees or merge (both stay the operator's, STATUS.md section E rules 1/2/5).

1. **Read the newest wake artifact.** The closing runner writes `.mission-runtime/lam/wake/<stamp>-<sid>.wake.json` (that plane is write-allowed, `settings.local.json:22-24`): `{ head_sha, batch, seat_name, model, effort, worktree_path (absolute), brief_source }`. The starter takes the newest by name sort.
2. **Compose the opening prompt.** Slice STATUS.md lines **1..before "## 10."** (the head brief). Because *runtime-plane docs are unreachable from a worktree*, **embed** the slab into `<worktree>/.wake-brief.md` and launch with a short prompt: "You are the &lt;seat&gt; seat; read `./.wake-brief.md` and begin."
3. **Launch.** Assert `worktree_path` exists and is **< ~150 chars** (MAX_PATH), then `Set-Location <worktree>; & claude -n <name> --model <m> --effort <e> "<prompt>"`. **No `-w`** (rule 2, checkbox off), **no `-p`** (interactive seat).

**Cost:** ~55–75 lines; parses one JSON artifact + one STATUS.md slice. Coded failure modes: empty wake dir, missing "## 10." marker, missing/over-long worktree path, `claude`-not-on-PATH. The only write is `.wake-brief.md` inside the operator-prepared worktree.

## Operator fork
**Embed the brief (recommended)** vs **`--add-dir` the main checkout so the seat reads the live STATUS.md.** Embed is robust against the measured "runtime-plane docs are unreachable from a worktree" fact and against PS/arg-length limits, but it snapshots the brief at launch and leaves a `.wake-brief.md` file the operator must ignore/clean; `--add-dir` stays current and leaves no file, but widens the seat's file-tool reach into the whole main checkout — the repository-of-record the worktree boundary exists to keep out of a session's hands (section E rule 1). Operator rules the coupling before build; everything else in the starter is mechanical.

## Residual under computer-use
The starter closes the copy-paste gap but changes nothing about the live-inject boundary, and an agent WITH computer-use defeats that boundary directly: it can type keystrokes into an already-interactive orchestrator's TTY window (the exact injection the CLI refuses), run `claude attach <id>` on a background session and type into it, or operate the desktop app to invoke `send_message` a headless runner cannot reach. It could also run `lam-wake.ps1` without the operator, and — worse — type/click through the operator's terminal to perform the non-delegable acts section E reserves: cut a `-w` worktree (rule 2), or drive `git merge`/push to land a branch to main with no human merge boundary (rules 1 and 5). The wake primitive's safety rests on a human being the only one at the keyboard; the starter only makes the LAWFUL path one command instead of a paste. Keep the 1800 s Stop-hook wedge (it re-prompts/holds a stray headless wake, buying detection time) and keep merge/push behind a human-controlled terminal; neither stops a computer-use agent that owns the desktop.

# ITEM 3 — THE SELF-RESOLUTION HOLE (HALT ruling path is agent-writable)

## Finding (confirmed)
A HALT's ANSWERED-ness is derived from agent-editable text, and the file that carries it is agent-writable on every layer. The goal evaluator's `Test-HaltAnswered` (`tools/lam/mission-goal-check.ps1:205-292`) reads the body line `**Status:**` (regex `:282`) and returns true if its first word is `ANSWERED` (`:288-289`). `Get-OpenHalts` (`:350-420`) enumerates `HALT-*` under `.mission-runtime/halts` and `.mission-runtime/lam` (`:353`) and drops any file that predicate accepts (`:411`). No operator signature, gate, or hash is consulted. An answered HALT file shows the marker is ordinary prose.

Neither guard protects the path: the sealed set (`evidence-common.ps1:1057-1064`) and the next-gen set (`evidence-hooks-next/.../evidence-common.ps1:4283-4287`) both exclude the HALT dirs; the parent tier `.mission-runtime` blocks only destructive ops (`:1052-1056`). The permission layer explicitly *allows* `Write/Edit(.mission-runtime/**)` (`.claude/settings.local.json:22-23`); its deny list names `.mission/gates`, `.claude`, `tools/framework`, `git push`, `rm` — but NOT the HALT dirs.

## Measured (drive, control held)
Guard, valid run (PSCustomObject inputs): protected controls `.mission-runtime/evidence/x.md` and `tools/framework/hooks/…` → **deny**; probe `.mission-runtime/halts/HALT-PROBE-01.md` and a HALT file under `.mission-runtime/lam/` → **allow**. Protected-set size measured = 6 members; the HALT dirs are in neither the protected set nor (for ordinary writes) the parent tier. Evaluator: a scratch HALT reading `**Status:** OPEN` gives `Get-OpenHalts` Count=1; after the *same agent* rewrites only that line to `ANSWERED`, Count=0. **One agent edit flips the goal verdict.** (First guard run's control failed — a hashtable `ToolInput` starved `Get-EntryField` (`:133-141`), which reads `.PSObject.Properties`; discarded per the apparatus trap, re-run with `[pscustomobject]`, control held.)

## Proposed rulings path (a swap, not a build)
Both sides already ship. Operator-write: `mission-gate.ps1 approve` mints `.mission/gates/<kind>-<id>.yaml` and refuses (exit 3, no bytes) in any session where `Get-LamNonOperatorConditions` (`:414-465`) fires. Evaluator-derive: the completion-acceptance detector (`mission-goal-check.ps1:720-756`) already enumerates operator gates, reads state via the shared `Get-LamGateState` (`tools/lam/lam-gate-class.ps1:123`, dot-sourced at `:104`), skips revoked, and matches `binds_sha256`.

- **Artifact:** new gate kind `halt-ruling` (a RECORDED RULING like `supersession` — no expiry, not consumed, revocable). `halt-ruling-<halt-id>.yaml` carries `binds`, `binds_sha256` (HALT bytes at ruling time), `ruling:` (decision), `authorized_by`, `created_at`, `revoked_at: null`. Minted by `mission-gate.ps1 approve -Kind halt-ruling -Id <halt-id> -Binds <halt-file> -MissionRoot .` — `approve` already computes `binds_sha256` from `-Binds`.
- **Evaluator change (exact):** replace `Get-OpenHalts:411` `if (Test-HaltAnswered -Text $t)` with `if (Test-HaltRuled -HaltFile $f -MissionRoot $MissionRoot)`. `Test-HaltRuled` (~20 lines, mirrors `:734-742`) joins the HALT to a live, unrevoked `halt-ruling-<id>` gate whose `binds_sha256` matches. `$MissionRoot` is already in scope; no signature change, no new dependency. `Test-HaltAnswered` is demoted to a non-authoritative citation reader.
- **Seat write-back becomes a citation:** a sidecar `.mission-runtime/halts/HALT-<id>.cite.md` (agent-writable, non-authoritative), never the ruled HALT body — so the ruled bytes stay frozen and `binds_sha256` keeps matching while the seat annotates freely.

**Cost:** small — one gate kind (+~10 lines mirroring the supersession lifecycle), one predicate swap (1 line changed, ~30 added), and new WP-3 instrument members — crucially the regression member: **seat-written `ANSWERED` with no gate must read OPEN.** Zero new libraries; both the operator-write channel and the gate-join read path already ship.

## Workflow change
Today: the operator pastes a ruling into chat, the seat writes `**Status:** ANSWERED`, the evaluator trusts it. Tomorrow: the operator runs one `approve` at their own terminal (refused in agent/hook/dispatch/non-interactive sessions), the seat cites, the evaluator derives ANSWERED from the gate — the same act the operator already performs for `completion-acceptance` (a HALT can already cite exactly such a gate), so no new muscle memory.

## Operator fork
Binding strictness is the one call. **(A)** id-only (gate exists + unrevoked, keyed on HALT id) — the operator never re-mints on a legitimate edit and citations are free, but a post-ruling MATERIAL rewrite goes unnoticed (answer stands over changed text). **(B)** additionally require `binds_sha256 == sha256(current HALT bytes)` — maximally tamper-evident, but any post-ruling edit re-opens the HALT until the operator reapproves. **Recommended: (B) + citation sidecar** — freeze the ruled bytes, annotate beside them, getting both tamper-evidence and a free citation.

## Residual under computer-use, and the item-1 dependency
The operator channel is a refusal, not a proof of humanity: a computer-use agent that spawns a fresh console with the harness vars stripped passes all four conditions and can mint its own `halt-ruling` gate (`mission-gate.ps1:74-84`, WP-4 T-25). This raises the cost of self-resolution from "one Edit into an agent-writable file" to "construct a scrubbed console and mint a gate"; it does not close the hole — that residual is already on the register. **True closure requires item 1's operator-only-writable mechanism.** The derive side (`Test-HaltRuled`) is deliberately location-agnostic — it matches on (HALT id, `binds_sha256`) regardless of whether the ruling artifact is a `mission-gate` gate, a second-account rulings dir, or a console-verb output — so it composes with whatever item 1 chooses. If item 1 only hardens the four-condition TTY assertion, this design inherits the T-25 residual and it must be carried on the register, NOT claimed closed — the exact mistake `mission-gate.ps1`'s own docstring records itself having made once.

# ITEM 4 — THE STOP-HOOK BUDGET

**Verdict: 1800 s is adequate with wide margin for the suite measured. The defect worth ruling on is not the margin — it is the fail-open, silent edge and the monotonic erosion behind a zero-margin floor.**

## What was measured (all re-derived, controls held)
- **Timeout**: `../<project>/.claude/settings.local.json:29-30` — `mission-goal-check.ps1 -Goal <goal> … -AsStopHook`, `timeout: 1800` (seconds = 30 min). Pointed at the current goal.
- **The goal's detectors** (canonical `.mission/goals/<goal>.yaml`): `halt_absent`, `file_exists`, `gate_present`, `validator_pass_count`, `instrument_exit0`, `verify_pass_or_dib`, and several `sidecar_present`. Only `instrument_exit0` is costly.
- **Dominant term** (the product suite `instrument_exit0` runs): the surveyor's full instrument run is timed externally and matches the instrument's own `elapsed_seconds` (independent-clock control); the composite run's inner pytest and the on-disk history fall in the same narrow range.
- **Composite wall** (measured, CLI mode, all detectors + verify + startups) tracks the inner pytest run closely, so the **entire non-instrument envelope is seconds** (verify, fast detectors sub-second, 2–3 PowerShell startups). Bounded <10 s.
- **Fresh-clone venv build** is a one-time fixed overhead of seconds (less when warm). A live checkout keeps a warm `src/.venv`.

**Margin**: the hook timeout is sized against the worst realistic suite wall with stated margin; a 2×-variance day and a fresh clone must both still fit.

## The two real exposures
**1. Erosion (trend).** C2 sits at **zero margin** when the runnable count equals the stored floor (`product.json`), and the floor ratchets up on every green close and never down. The suite can only grow. The slack absorbs a long runway of growth, but strictly **monotonic**; it never recovers, and steepens if infra-gated skips are ever un-skipped into heavier execution.

**2. The edge is fail-open AND silent.** There is exactly one timeout in the chain — the 1800 s hook timeout; neither instrument nor runner caps the suite (`tests/lam/instrument-<goal>.ps1:215`; no `--timeout`). So one hung test burns the full 30 min. On the kill: `verdict.yaml` (written only at `mission-goal-check.ps1:1076`) is **not rewritten** → the stale verdict stands; the capture (persisted only at `lam-instrument-run.ps1:239/:242`, after the instrument returns) is **never written** → only a stale prior tally remains. **The persistence cure covers a completed-but-red run, not a timeout-kill** — persistence is post-completion, so the killed run is SILENT on the mission plane. `trap{}` (`:91-97`) fires on a PowerShell exception, not an external kill. The design comment concedes it (`:950`): "a hook that outran its own timeout would be silently skipped by the harness … worse than no gate at all"; the 1800 s hold is measured. **Net: a timeout delays the stop 30 min, then a would-be BLOCK silently becomes an effective APPROVE — the session ends unverified.**

The existing mitigation is the hook-mode short-circuit (`:945-966`): the instrument runs only when detectors 1–4 pass, so the budget is stressed **only in the close-prep/MET window**. Good, but it does nothing for a hang once you are in that window.

## Recommendation (propose, not build)
Keep 1800 s as the backstop (a wide margin is right for a 30-min gate). Add a **900 s in-suite wall guard** inside `Invoke-M2` (`instrument-<goal>.ps1:216-224`) — about twice the worst observed suite wall: on expiry, kill the pytest process tree and emit a real red `TALLY … pytest_exit=124 … elapsed_seconds=<n>` sentinel. The instrument then **completes red**, so the persistence path runs, `instrument_exit0` reads exit≠0 → **fail-closed NOT_MET with a reason on disk**, and the verdict IS rewritten — all inside the harness backstop. **Build cost:** small and localised — one guarded-invocation edit plus, optionally, `pytest-timeout` in the product deps; the sentinel/persistence plumbing already exists. It touches a protected instrument, so it needs the protected-instrument rewrite handover (whole-file re-authorship, byte-invariant pre-declared) and a re-derived floor run.

## Fork for the operator
Accept the margin and freeze — betting no test ever hangs and the suite stays inside the budget before the next budget review — **versus** one reviewed instrument edit that turns the sole fail-open, silent timeout into a legible fail-closed red. The change costs a protected-instrument handover + a re-derived floor; it removes the only fail-open path in the goal gate and makes every over-budget run legible.

## Residual under computer-use
An agent cannot shrink the real suite wall, but against this gate it could: (a) **deliberately trip the silent edge** — introduce or await a hanging test so the hook is killed at 1800 s fail-open, ending its session unverified while the plane shows only the prior green capture; (b) **exploit stale residue** — after a kill, `verdict.yaml` and `instrument-runs/*.tally.txt` keep their last (green) contents, and a later reader glancing at `instrument-runs/` sees a plausible green TALLY with an only-slightly-old mtime; (c) **forge the gitignored capture** — `lam-instrument-run.ps1:63-69` states the capture is "NOT durable evidence," unbound by any gate sha, so an agent could overwrite it with a fabricated green TALLY. None forge a MET verdict (the verdict keys off the live exit code of a run that actually completed, and the validator/gate/halt detectors are disk-bound and provenance-checked), but all three exploit that a killed run is silent and its residue is stale-yet-trusted-looking. The proposed in-suite timeout closes (a) and shrinks (b); (c) remains until the capture is bound (that ruling is owed).
